# Эмулятор стены Kilter для Linux

Ноутбук притворяется стеной Aurora по Bluetooth Low Energy. Телефон подключается к нему так же,
как к настоящей стене, и шлёт те же пакеты. Эмулятор их разбирает, рисует подсвеченные зацепки
и пишет журнал: каждый принятый кусок (до 20 байт), задержки между ними, ошибки протокола.

## Установка (один раз)

Ubuntu / Debian / Mint:

    sudo apt install python3-venv python3-tk bluez
    python3 -m venv --system-site-packages ~/kilter-venv
    ~/kilter-venv/bin/pip install bless

Fedora: `sudo dnf install python3-tkinter bluez`, дальше те же две команды с venv.

Отдельное окружение (venv) нужно, чтобы не трогать системный Python. `--system-site-packages`
даёт ему доступ к системному tkinter для окна.

## Запуск

    cd папка-с-эмулятором            # здесь лежат kilter_emulator.py и holds.json
    bluetoothctl power on
    ~/kilter-venv/bin/python kilter_emulator.py

Сначала можно проверить окно без Bluetooth: `~/kilter-venv/bin/python kilter_emulator.py --selftest`.
Без графики: добавьте `--no-gui`, журнал пойдёт в терминал.

## Подключение с телефона

1. В приложении переключите «Мок → Стена», нажмите «Подключить стену».
2. В списке выберите **Emu@3**. Если там имя ноутбука или «Неизвестное устройство», выберите его:
   Android иногда показывает закешированное имя.
3. Если в статусе написано «API 2 (по имени)», поставьте «Версия протокола стены → API 3».
4. Нажимайте «Дальше»: в окне эмулятора загораются те же зацепки, что на превью в телефоне.

## Версия протокола

По умолчанию эмулятор строгий, как настоящая стена: `Emu@3` принимает только пакеты API 3,
`--name Emu@2` — только API 2. Пакет другой версии не рисуется, а в журнале появляется красная строка.
Так ловится неверная «Версия протокола стены» в приложении. `--lenient` принимает обе версии.

## Обрыв связи

При закрытии окна или Ctrl+C эмулятор разрывает соединение с телефоном, как выключенная стена,
и телефон начинает переподключаться. Отключаются только устройства, которые подключились
после запуска эмулятора и не сопряжены с ноутбуком: телефон через Web Bluetooth не сопрягается,
а наушники, мышь и клавиатура сопряжены и остаются подключёнными.

## Что меняется на ноутбуке

Ничего постоянного. Пока работает скрипт, ноутбук рекламирует «стену»; при закрытии окна или Ctrl+C
реклама снимается. Bluetooth-имя ноутбука не меняется. Флаг `--set-alias` меняет имя на время работы
и возвращает при выходе; если скрипт упадёт, вернуть вручную: `bluetoothctl system-alias "Старое имя"`.

## Если не работает

- «Не удалось запустить Bluetooth»: проверьте `systemctl status bluetooth` и `bluetoothctl show`
  (должно быть `Powered: yes`). На очень старых BlueZ (до 5.48) реклама может требовать
  запуска службы с флагом `--experimental`.
- Ошибка прав D-Bus: добавьте пользователя в группу `bluetooth` (`sudo usermod -aG bluetooth $USER`,
  затем перелогиньтесь).
- Телефон не видит эмулятор: включите на телефоне геолокацию (Android требует её для поиска BLE),
  поднесите телефон ближе, перезапустите скрипт.

## Чем эмулятор отличается от настоящей стены

Он полностью повторяет сторону телефона: поиск, подключение, сервисы, запись кусками по 20 байт,
задержки и обрывы Bluetooth. Не повторяет он сторону стены: поведение прошивки контроллера
(например, гасит ли её пустое сообщение), соответствие номеров светодиодов физическим зацепкам
и реальные оттенки диодов. Это проверяется пятью минутами на настоящей стене.
